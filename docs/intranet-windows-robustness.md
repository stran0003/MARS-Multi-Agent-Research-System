# 内网模型与 Windows 运行兼容性

更新：2026-10-22。范围是公共模型适配、文档交接、文件持久化与 Windows 字节读写；不改变已批准的研究代码、数据和实验参数。

## 修改原则

| 类别 | 处理方式 | 仍需满足的条件 |
| --- | --- | --- |
| 文档外观 | 接受 BOM、CRLF、完整 Markdown 代码围栏、一致的重复 frontmatter；允许附加说明和空的重复正文 | 必须有可解析的结构材料；相互矛盾的字段需要修正 |
| 描述性元数据 | 标题、时间、摘要、来源路径、模型抄写的方案哈希，以及非空说明文字的最低字数，降为提示 | 项目身份、必要字段类型和真实执行参数不靠猜测补齐 |
| 阶段交接 | 对比实验矩阵、种子、预算及参数；不因方案文字改变或抄错整份文档哈希而拒收 | 真实 YAML、启动入口、数据文件、模型参数、批准范围必须一致 |
| 工作区清单 | 接受 JSON 缩进、字段顺序及换行差异；Windows 不强制 POSIX 0644/0755 | 仍核验实际文件内容、路径范围、清单身份及修改来源；拒绝链接越界 |
| 运行结果 | 保留真实结果证据与收据校验 | 不能把进程退出、格式通过、推理内容或残缺输出当作实验成功 |

文档兼容逻辑集中在 `frontmatter_parser`、`validator` 和 `experiment_contract`。新模型输出格式在这些边界处理，避免每个 Agent 自行清洗或补造材料。执行确认仍绑定真实配置；必要的重新确认和用户审批不会被跳过。

## OpenAI 兼容接口

普通完成请求和 ZCode 转发请求都显式发送 `stream: false`。调用使用 OpenAI SDK 的公开 `with_raw_response.create` 接口获取实际 HTTP 内容，再统一识别 JSON 或强制 SSE；不再假定返回值一定有 `.choices`。

支持普通 JSON、SDK 对象、JSON 字符串、SSE `data:` 事件、CRLF、心跳注释及 `[DONE]`，并组装分块工具参数。网关仅发 `[DONE]` 而没有重复的 `finish_reason` 时，完整响应仍可使用；断流、`length` 截断、服务端错误和只有思考而没有最终答复时明确失败。

`message.reasoning`、`delta.reasoning` 和 `reasoning_content` 不作为公开答复或执行结果。ZCode 私有传输保留后续工具轮次所需的原始推理字段；公开 MARS 完成对象与轨迹继续排除它们。强制思考的内网接口可采用已有的 `gateway_plain_request` 设置，省略不支持的思考开关、模板参数及可选扩展；解析兼容本身默认生效。

## 等待时间

公共模型默认及部署配置下限为 **720 秒**。主控、各阶段、研究子角色、审核、命令行与模型连接测试使用统一规则；旧配置低于 720 秒自动提升，3600 秒等更长设置保留。Focused/实验研究配置叠加不能缩短已有更长等待。前端模型连接测试至少等待 750 秒。

这不是无限等待：用户取消、总任务预算、工具执行超时与普通项目列表请求仍独立工作。内网反向代理若先行断开连接，需要同步调整其服务端超时；客户端不能延长已被服务器关闭的连接。

## Windows 文件与进程

持久化统一使用 `harness.persistence`：已关闭并刷盘的临时文件原子发布，Windows 共享冲突（WinError 5/32/33）最多重试 5 秒，跨进程锁复用已有 FileLock。持续拒绝访问仍报告错误，原文件保留，不以先移走原文件或直接截断写入降级。上下文、快照、研究代码及回滚记录、运行状态、数据索引和导出等调用接入该公共层。

具体修复包括：

- Windows 目录刷盘不调用 POSIX `os.open/fsync`；代码仓读取使用已有 Windows 原生句柄路径，实际验证不访问 `os.O_DIRECTORY`。
- 工作区哈希、代码 blob、执行归档及日志采用二进制描述符，避免 Windows CRT 转换 CRLF、Ctrl-Z，或破坏二进制包。
- 工作区权限检查仅在支持 POSIX 模式的平台执行；Windows 不调用不存在的 `fchmod`。原有文件类型和内容检查保留，额外识别 Python 3.11 `is_symlink` 漏掉的 junction。
- 冻结上下文按实际写入字节记录哈希；仅旧 UTF-8 上下文收据兼容 LF/CRLF 差异，不将此宽容扩展到代码、实验数据或结果。
- 子进程默认 UTF-8，避免中文路径的 UTF-8 控制文件被 GBK 解码；保留操作者显式编码配置。

没有增加新的运行依赖，也不要求重装 Python 环境。

## 验证与边界

真实 DeepSeek Flash 的普通 JSON、ZCode 原始响应转发、SDK SSE 三种调用均通过。强制 SSE 和两种 reasoning 字段使用离线协议样本覆盖，未声称已连接用户内网服务。

真实 CPU 验收 `2026-10-22T1403_zcode_coding_execution_acceptance` 通过：同一 ZCode 会话先遇到真实入口错误，再修复并完成 20 个算术样本，MSE=0，Writing 完成报告与证据导出；原始失败保留。证据在本地 `runs/20261022T140333_coupled_validation/acceptance.json`。这是 Coding→执行修复→Writing 的合成 CPU 验收，Idea/Experiment 明确跳过，不是 PIM 研究效果验收。

回归包括真实 Windows 占用句柄、拒绝访问后原文件保留、中文路径、junction、二进制/CRLF 拷贝、配置超时、文档宽容与错误参数拒收。历史测试中依赖未提供研究归档、POSIX 权限或 Windows 符号链接创建特权的用例不能冒充已通过；本轮针对支持的 Windows 路径另行验证。目标内网端点的长响应、网关超时、特定模型工具协议仍需部署后验收。
