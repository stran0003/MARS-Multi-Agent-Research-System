# 新会话停在主控读取阶段

## 原因

真实会话连续两轮只做目录浏览、资料读取，没有创建任务。每轮达到 12 步上限后仅提示“尚未取得任务创建、任务启动依据”。服务和模型调用均正常。

上下文清单显示：隐藏的默认工作预算为 24,000，而工具声明约 17,072、规则和任务约 18,187（均为 UTF-8 字节上界估算），固定开销已经超过预算。打包器在模型处理之前就把刚列出的目录卸载为引用。模型再次列目录或读取引用，下一次又被卸载。旧压缩状态还会在后续调用中重复恢复。

## 修改

- 取消隐藏的默认 24K 工作预算，读取主控 `loop.input_token_budget`；模型窗口只提供容量边界，不扩大显式输入预算。额外配置的 `model.runtime.working_context_tokens` 仍作为更小的工作预算生效。
- 最近一次主控决策产生的整批工具结果，在下一次模型调用前完整保留，包括目录、搜索结果和读取内容；后续可以正常压缩，不作为永久缓存。
- 打包规则版本或预算改变时，从保留的原始材料重新打包，清除旧规则的过度卸载决定，不改写原始对话和工具证据。
- 耗尽步骤时明确显示处理步数、未完成事项和继续入口；不将未创建任务描述成仿真失败。

## 验证

- 新增真实文件/纯打包回归测试：目录可见、旧压缩迁移、批量结果保留、256K 配置优先于 1M 模型容量、步骤上限提示。
- 相关首轮测试 69 项通过；预算联动补充后 62 项通过；3 个改动模块通过 mypy。
- 扩展主控回归 170 项通过；2 项 Windows 符号链接测试在创建测试文件时遇到 WinError 1314（账户没有创建符号链接权限），未验证该平台分支。
- 本机使用原会话的正式“继续”接口恢复：主控读取源码后，遇到未登记执行入口，转交普通 Coding，成功创建并启动任务。该结果证明会话调度恢复，不代表基线训练或研究全流程已完成。

## 部署说明

本机已重启部署主控上下文修复。随后通过正式配置接口显式设置主控工作预算 262,144，使预算修正即时生效，不中断已启动的 Coding。API Key、模型、输出额度及其他 Agent 配置保持不变。
